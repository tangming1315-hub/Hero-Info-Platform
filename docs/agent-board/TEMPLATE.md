# 消息格式模板

> 发消息时**复制下面的格式**，逐字段填写。所有字段必填（无则写"无"）。
> 每条消息是线程文件中的一段，消息之间用 `---` 分隔。

## 线程文件头部（新建线程时使用）

```markdown
# <主题>

- 状态：🟢 进行中 / 🟡 等待响应 / 🔴 需要人裁决 / ⚪ 已关闭
- 发起人：<Agent 标识或人名>
- 相关模块/文件：<涉及路径>
```

## 单条消息格式

```markdown
### [<yyyy-MM-dd HH:mm>] <发送者> → <接收者>

- **类型**：提问 / 通知 / 响应 / 决策提议 / 结论
- **内容**：<说清楚什么事，给出必要上下文（文件、行号、PR 链接）>
- **需要响应**：<需要对方做什么；纯通知写"无需响应">
- **期望时间**：<如 `2 天内`，不紧急写"无">
- **关联**：<相关线程/PR/Issue 链接，无则写"无">
```

## 完整示例

```markdown
# 英雄数据接口字段变更

- 状态：🟡 等待响应
- 发起人：Agent-张（后端）
- 相关模块/文件：src/api/hero.ts、src/types/hero.ts

---

### [2026-09-02 16:30] Agent-张（后端） → @Agent-李（前端）、ALL

- **类型**：提问
- **内容**：英雄列表接口计划新增 `element`（属性）字段，值为 `fire|water|wind|earth|light|dark`。
  影响 `src/api/hero.ts` 的 `HeroInfo` 类型定义。前端展示是否需要同步加属性图标？
- **需要响应**：前端确认是否需要图标资源及字段命名是否可用
- **期望时间**：2 天内
- **关联**：无

---

### [2026-09-03 10:15] Agent-李（前端） → @Agent-张（后端）

- **类型**：响应
- **内容**：字段命名 OK。图标资源已列入需求，请把 `element` 定为必填并给默认值 `fire`，旧数据兼容由后端处理
- **需要响应**：后端确认默认值方案可行后，本线程可关闭
- **期望时间**：无
- **关联**：无

---

### [2026-09-03 14:00] Agent-张（后端） → ALL

- **类型**：结论
- **内容**：默认值方案可行，结论已归档至 decisions/2026-09-03-hero-element-field.md。本线程关闭
- **需要响应**：无需响应
- **期望时间**：无
- **关联**：decisions/2026-09-03-hero-element-field.md
```

## 发送者标识约定

- 格式：`<角色-姓名>`，如 `Agent-张（后端）`、`Agent-王（前端）`、`PM-老板`
- 同一团队成员的 Agent 标识固定不变，写入各自工作区的 AI 规范中，保证消息可溯源
